# P24 Step 04

This step adds the initial deterministic `content_package.json` generator path.

Part of #326. Closes #335 after the PR merges.

## Goal

Provide a safe first implementation path that can inspect an existing Short or explainer production folder, detect current assets, and write a contract-shaped `content_package.json` with pending placeholders for future packaging, retention, rights, export, and editorial review work.

## Implementation status

The implementation is deterministic and local-file-only.

It does:

- read an existing production folder;
- detect existing production plans;
- detect existing visuals;
- detect existing narration files;
- detect existing subtitles;
- detect existing rendered preview or final video files;
- detect existing source evidence files;
- detect existing checkpoint files;
- detect Short source manifest and clips;
- detect explainer concept and clip pool manifest;
- populate required `content_package.json` fields;
- mark future P25, P26, P27, and P29 fields as pending;
- default `publish_allowed` to `false`;
- default editorial approval to `not_approved`;
- write the package deterministically for tests.

It does not:

- generate titles;
- generate thumbnails;
- score retention;
- score rights risk;
- verify licenses;
- export platform folders;
- approve editorial status;
- render videos;
- upload content;
- publish content;
- bypass workflow gates.

## Public functions

`src/content_package.py` exposes:

```text
build_content_package(production_dir, *, content_type, ...)
write_content_package(production_dir, *, content_type, output_path=None, ...)
```

`build_content_package` returns a dictionary that follows the P24 schema.

`write_content_package` writes that dictionary to `content_package.json` by default, or to a caller-provided output path.

## Supported content types

Initial supported content types:

- `short`;
- `explainer`.

Future content types such as `long_form` remain schema-supported but are not generated by this step.

## Short production detection

For Short production folders, the generator checks:

| Asset | Expected path |
| --- | --- |
| run manifest | `{run_dir}/manifest.json` |
| extracted clips | `{run_dir}/clip_*.mp4` |
| production plan | `{production_dir}/production_plan.json` |
| visuals | `{production_dir}/image*.png` |
| narration | `{production_dir}/narration_*.mp3` |
| captions | `{production_dir}/subtitles.srt` |
| preview render | `{production_dir}/preview_video.mp4` |
| publish candidate render | `{production_dir}/publish_video.mp4` |
| image source evidence | `{production_dir}/image_sources.json` |
| preview metadata | `{production_dir}/preview_video.mp4.metadata.json` |

`preview_video.mp4` is always marked `publication_eligible: false`.

`publish_video.mp4`, when present, is still marked `publication_eligible: false` until P25, P26, P27, and P29 controls exist.

## Explainer production detection

For explainer production folders, the generator checks:

| Asset | Expected path |
| --- | --- |
| concept copy | `{campaign_dir}/concept.yaml` |
| clip pool manifest | `{campaign_dir}/clip_pool/manifest.json` |
| explainer plan | `{production_dir}/explainer_plan.json` |
| beat visuals | `{production_dir}/beat_*.png` |
| comparison collage | `{production_dir}/beat_comparison_collage.png` |
| narration | `{production_dir}/narration_*.mp3` |
| captions | `{production_dir}/subtitles.srt` |
| current final video | `{production_dir}/final_video.mp4` |
| image source evidence | `{production_dir}/image_sources.json` |
| checkpoint | `{production_dir}/checkpoint.json` |

Current explainer `final_video.mp4` is marked as review-required and `publication_eligible: false` because packaging, rights, export, and editorial gates are not complete.

## Placeholder states

The generator uses these placeholder states:

- `pending_p25` for packaging and retention;
- `pending_p26` for rights and monetization;
- `pending_p27` for platform exports;
- `pending_p29` for editorial review;
- `not_approved` for approval state;
- `not_publish_ready` for platform publish state.

## Stop conditions

Stop generator work if:

- generated packages are described as publish-ready;
- `publish_allowed` defaults to `true`;
- `preview_video.mp4` is publication eligible;
- `publish_video.mp4` skips rights or editorial review;
- explainer `final_video.mp4` is treated as already approved;
- source evidence is treated as copyright clearance;
- broadcast clips are treated as rights-cleared by default;
- platform exports are generated inside this step;
- upload or publishing is introduced;
- workflow gate bypass is requested.

## Guardrails

- No automatic approval.
- No automatic release.
- No automatic rendering.
- No automatic publishing.
- No automatic upload.
- No automatic rights clearance.
- No automatic monetization approval.
- No automatic legal approval.
- No automatic platform export.
- No automatic editorial approval.
- No workflow gate bypass.
- No implementation without scoped issue and PR.
- No merge without exact-head CI.
- No secret values in evidence.
- No private runtime values in notes.
- No customer data exports.
- No external package exports.

## Validation

Covered by:

```text
tests/integration/test_p24_step_04.py
```

The validation creates deterministic Short and explainer fixture folders, builds packages from existing files, confirms required current assets are captured, verifies pending placeholders, confirms preview/final outputs are not publication eligible, writes `content_package.json`, reloads it, and checks P24 CI wildcard coverage.
